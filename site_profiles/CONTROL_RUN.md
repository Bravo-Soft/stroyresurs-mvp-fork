# Автоматический контрольный прогон — задача 7

Этап `control` очереди выполняет явно заданную небольшую выборку:
свежий HTML/DOM → Markdown → фактический запрос модели → обработанные данные →
локальные DOCX → метрики и ZIP доказательств. Источником характеристик остаётся
видимая страница; содержимое вложений, документов и PDF не читается.
Граф, Kafka, production pipeline и автоматическое применение профиля не запускаются.

## Запуск

Запускайте из рабочей копии исходников в `codex_work`:

```bash
python -B -m site_profiles.profile_queue --queue /ai/projects/stroy-resurs/codex_work/queues/control_001 init --limits limits.json
python -B -m site_profiles.profile_queue --queue /ai/projects/stroy-resurs/codex_work/queues/control_001 add job.json
python -B -m site_profiles.profile_queue --queue /ai/projects/stroy-resurs/codex_work/queues/control_001 run --drain
python -B -m site_profiles.profile_queue --queue /ai/projects/stroy-resurs/codex_work/queues/control_001 status
```

До запуска передайте ключ через **CONTROL_MODEL_API_KEY** в окружении диспетчера.
Он передаётся только процессу control, не включается в SQLite, снимок задания,
запросы JSON или архив доказательств. Не помещайте секрет в manifest.
Для браузера установите PLAYWRIGHT_BROWSERS_PATH на уже установленный Chromium.
Программа не устанавливает браузер, не скачивает токенайзер и не запускает сервисы.

Пример limits.json — лимиты очереди:

```json
{"workers": 2, "per_host": 1, "model_slots": 1, "browser_slots": 1,
 "stage_seconds": 600, "job_seconds": 1800, "memory_mb": 2048, "attempt_mb": 200}
```

Слоты модели/браузера резервируются на всё время этапа (консервативная оценка).
По умолчанию они равны нулю: живой этап нужно разрешить явно при создании очереди.
Каждый работник выполняет страницы и запросы последовательно. Число параллельных
модельных и браузерных этапов не превышает выделенных слотов.

job.json:

```json
{
  "version": 1,
  "url": "https://factory.test/",
  "profiles": "candidates",
  "stages": [{"kind": "control", "manifest": "control.json"}]
}
```

Допустима цепочка discover → markdown → control. Найденный отчёт структуры
передаётся контролю для проверки покрытия; сохранённые результаты первых этапов
не заменяют свежую загрузку внутри control. Входные профили и код фиксируются
очередью; обновление исходного YAML не изменяет уже поставленное задание.

control.json:

```json
{
  "version": 1,
  "company": {"name": "Завод", "url": "https://factory.test/"},
  "model": {
    "base_url": "http://model-gateway:4000/v1",
    "name": "gemma4-31b-nvfp4",
    "key_env": "CONTROL_MODEL_API_KEY"
  },
  "limits": {
    "max_pages": 10, "max_calls": 10, "max_tokens": 200000,
    "fetch_seconds": 30, "model_seconds": 180, "host_delay": 1,
    "html_bytes": 5000000, "response_bytes": 4000000, "output_tokens": 4096
  },
  "pages": [
    {
      "url": "https://factory.test/catalog/pump/",
      "role": "product", "split": "control", "transport": "http",
      "expected": "product",
      "reference": {
        "selectors": ["main", "#specifications"],
        "origin": "Независимая проверка содержательных блоков страницы"
      }
    },
    {
      "url": "https://factory.test/catalog/other/",
      "role": "product", "split": "holdout", "transport": "browser",
      "wait_for_selector": "h1",
      "interactions": ["#specifications-tab"],
      "reference": {
        "selectors": ["main", "#specifications"],
        "public_selectors": ["#specifications"],
        "origin": "Независимый holdout и проверенная публичная вкладка"
      }
    }
  ]
}
```

`reference` следует контракту [проверки Markdown](MARKDOWN_VALIDATION.md), включая
мотивированные exclusions. Она не строится автоматически из удалений кандидата.
Ожидание `expected` может быть product, not_product либо unspecified (по умолчанию).
Подтверждённое расхождение с ожиданием даёт fail. Роль negative — отрицательный
товарный пример: выдача прошедшего числовой гейт товара считается дефектом.
Company/distributor сохраняют структурированные данные без товарной карточки.
Один URL может выполнять обе роли; одинаковая пара URL+роль не повторяется.
URL control и holdout не должны пересекаться. Локальные ID карточек производятся
из конечного URL и служат только связью внутри доказательств, это не ID графа.

Выборка обязательна и целиком должна помещаться в max_pages (максимум 100).
Контроль не обрезает её молча и не заменяет полный обход сайта. Необязательный
structure_report — путь к отчёту задачи 4; непокрытая выборка и открытые ограничения
сохраняются. Предоставленные пользователем обязательные URL включите в pages.

## Свежесть, видимость и извлечение

HTTP получает страницу заново без production-кэша, с no-cache/no-store.
Сохраняются тело ответа, декодированный HTML, время, цепочка редиректов и SHA256.
Только HTML с HTTP 200 допускается к извлечению. Редиректы проверяются до загрузки.
Сохранённый HTML из прошлых прогонов не используется как сетевой fallback.

Browser создаёт новый контекст, дожидается networkidle и видимого wait_for_selector
(по умолчанию первый reference selector либо body). Сохраняет снимки до/после
явно заданных кликов. Клик требует единственный видимый элемент; после каждого
клика ожидается завершение сетевой активности. Произвольный JS не исполняется
оператором через manifest. POST/другие небезопасные методы, WebSocket, service workers
и загрузка документов блокируются; допускаются GET/HEAD в разрешённом периметре.
Статические ресурсы не фильтруются классификатором страниц, навигация фильтруется.
Заблокированные сторонние ресурсы остаются в отчёте как ограничение.
Если сайт требует POST API, сторонний CDN, другой домен, специальные состояния
или иную логику взаимодействия, полнота не подтверждается; защита не отключается.

Для диагностик `v-kirpich.ru` и `ryazanbrick.ru` страница может задать
`"fresh_http_render": true` вместе с `"transport": "browser"`. Разрешённые
GET-ресурсы загружаются заново штатным HTTP-клиентом и передаются Chromium;
сохраняются URL, HTTP-статус, размер и SHA256 каждого ответа, исходный документ
и снимки браузера. Старый HTML не подставляется. DNS, TLS, ограничения хостов,
методов, редиректов и классификатор остаются обязательными.
Для `ryazanbrick.ru` дополнительно разрешён явный `"network_interface": "ens18"`:
исходящий сокет HTTP-рендера привязывается к указанному существующему интерфейсу.
Имя проверяется, привязка записывается в `fetch.json`; системные маршруты не
меняются. Запросы модели этим параметром не затрагиваются. Автоматического
перехода на другой интерфейс нет; неизвестный интерфейс даёт ошибку контроля.
Этот параметр контрольного manifest не настраивает транспорт рабочего краулера.
Для GET-документа РКЗ ответы502/503/504 допускают не более двух повторов с паузой.
Каждый ответ, включая неуспешный, сохраняется с HTTP-статусом, телом и SHA256.
После исчерпания попыток ошибка остаётся ошибкой; ответы4xx и запросы модели
этим механизмом не повторяются.

Используются штатные html_to_markdown, AITunnelClient и DOCXGenerator.
Числовой гейт и последовательность восстановления таблиц/видимых разделов вынесены
в общий product_preparation.py и вызываются также main.py. Порог >=3 не менялся.
Штатный промпт не изменён. Для контрольного этапа поддерживаются single-call модели
из действующего клиента; неизвестная модель отклоняется до постановки.
Данные, допустимые после гейта, сохраняются в DOCX. RTF/Office и вложения не
запускаются; исходный DOCX не удаляется. Фотографии отдельно не скачиваются.

Сохраняются полный Markdown, подготовленный источник, JSON фактического запроса,
ответ модели, выделенное реально переданное окно источника и его отдельная
Markdown-проверка. Усечение не подменяется симуляцией. При обычной потере данных
карточка блокируется. Для штатного компактного представления больших таблиц
сохраняются исходный HTML, сигнал потери во входе и результат восстановления;
это требует отдельной проверки и не объявляется успешной приёмкой.

Max_calls ограничивает число запросов; max_tokens ограничивает новые вызовы
по предварительной оценке плюс максимальному ответу. Точный usage известен только
после ответа провайдера: один запрос может превысить предварительную оценку;
превышение фиксируется и не позволяет следующий вызов. Неизвестный usage явно
помечается оценочным. У модели нет внутренних автоматических ретраев этого этапа.

## Статусы и доказательства

В каждой странице: source.html, при HTTP response.body, fetch.json, markdown.md,
markdown_check.json, prepared_source.txt, request_N.json, response_N.json,
model_calls.json, model_input.txt, model_input_check.json, extraction.json,
prepared_product.json, card/*.docx и page.json — по фактически достигнутым стадиям.
При browser дополнительно before.png/after.png. progress.json обновляется после
каждой страницы; результаты ошибки и прерывания сохраняются.

В пакете: summary.json, metrics.json, SUMMARY.txt, evidence_sha256.json и evidence.zip.
Свод содержит run_id, связь с заданием/попыткой, хеши кода/профилей/manifest,
окружение, модель и хеш системного промпта. Числа ТХ учитываются только после
реального сохранения карточки: полный card_spec_counts, card_sources с URL/ID/хешами,
медиана и среднее. Отказы ниже порога и сбои генератора не создают фиктивных записей.
Confidence рассчитывается прежней формулой 0.3F + 0.4E + 0.3V; это диагностическая
метрика переписи. С 12.11.2026 приёмка свежего control в profile-review v3 использует отдельный quality_confidence по независимому постраничному аудиту; этот исторический балл не является порогом качества.

Fail означает подтверждённую ошибку представления/ожидания/генерации.
Отсутствие ключа, сети, браузера, неполная загрузка либо неопределённый ответ модели
дают uncertain с причиной. Даже успешная цепочка остаётся uncertain до смысловой
проверки: этот этап не выдаёт автоматического принятия профиля. HTTP не подтверждает
вычисленную браузером видимость; снимки экрана тоже не заменяют независимое судейство.

После аварии с незавершённым запросом control не повторяется автоматически:
провайдер мог уже выполнить генерацию. Очередь сохраняет неполные доказательства
и infrastructure_*.json, переводит задание в review. Полностью записанная квитанция
по-прежнему подхватывается без повторного исполнения. Новую попытку после разбора
создайте новым заданием/label. Это предотвращает скрытое повторение платных вызовов.

## Изоляция

Живой этап требует Linux + bwrap: корень файловой системы и исходники read-only;
единственная записываемая папка проекта — текущая попытка, /tmp смонтирован в неё.
PID namespace и die-with-parent завершают браузер при гибели работника/диспетчера.
Python audit hook дополнительно блокирует production pipeline, граф, внешние записи
и произвольные subprocess (разрешён только Playwright driver при browser=true).
HTTP-клиент закрепляет проверенный DNS, запрещает приватные IP сайтов, произвольные
порты и любые endpoint модели кроме указанного chat/completions. Порты графа/БД/Kafka
запрещены также для модели. Ключ не передаётся странице/браузерному контексту.

Ограничиваются время, CPU, суммарный RSS дерева процессов и объём результатов.
Для HTTP действует также RLIMIT_AS; для Chromium он отключён из-за огромного
резервирования виртуальных адресов, используется контроль RSS диспетчером.
Проверки памяти/диска периодические, не аппаратная cgroup-квота. Это исполнение
доверенного кода и штатного браузера, не песочница для враждебных нативных модулей.
При отсутствии обязательной изоляции нет запуска без защиты: сохраняется причина.

Код проверки профиля, операторская приёмка и применение остаются разделены.
