# Обнаружение структуры сайта

Этап задачи 4 строит карту обнаруженных URL и разнообразную выборку для дальнейшей
проверки профиля. Он не создаёт товарные карточки, не меняет YAML и confidence,
не запускает очередь, загрузчик графа или продовый pipeline.

Используются существующие `SiteMapParser`, `URLCategorizer`, `SmartURLNormalizer`,
`WebCrawler._extract_additional_links` и `WebCrawler.fetch_page`. Это сохраняет
разбор robots/sitemap index/XML/HTML/text/gzip, товарных сеток, onclick/data-URL,
публичных окон Tilda, профильных товаров лендингов и штатную лестницу загрузки.
В sitemap добавлен опциональный `discovery_sink`: он видит URL до языковой
фильтрации и сообщает об ограничениях сканирования/подкарт/глубины. Без sink
рабочий обход сохраняет прежнее поведение.

## Запуск

Из рабочей копии исходников в `codex_work`:

```bash
python -B -m site_profiles.discover_structure https://factory.test/ \
  --profiles /ai/projects/stroy-resurs/codex_work/кандидаты \
  --manifest /ai/projects/stroy-resurs/codex_work/корпус/manifest.json \
  --output /ai/projects/stroy-resurs/codex_work/прогоны/новый_идентификатор \
  --pages 60 --urls 10000 --depth 5 --seconds 300 --sample 30 \
  --control https://factory.test/catalog/known-product/ \
  --holdout https://factory.test/catalog/check-product/
```

`--control` и `--holdout` повторяемые. `--no-sitemap` явно выключает проверку карт
и оставляет соответствующее ограничение в отчёте. Вместо `--manifest` можно
явно указать `--live`: будут работать штатные HTTP/browser-транспорты, без LLM.
Режим по умолчанию не выбирается: нужно указать один из двух.

Нужен новый выходной каталог строго внутри проектного `codex_work`. Проверяются
эффективные пути, включая символьные ссылки. Существующие каталоги не очищаются
и не перезаписываются. Все выходные пути Config, TMPDIR и XDG_CACHE_HOME направлены
в этот прогон; graph_db_enable=False, main/очередь/загрузчик не вызываются.
Сеть для сохранённого корпуса не используется: отсутствующий URL получает
`not_in_saved_corpus`, без скрытого резервного запроса.

Профиль выбирается до создания краулера; невалидная схема v2 блокирует запуск.
В режиме обнаружения исключения профиля проверяются и при допуске в очередь,
и перед транспортными переходами, включая редиректы. Дополнительные домены
разрешаются только действующим профилем; ссылка/canonical не расширяет периметр.
Документы и изображения учитываются как ссылки, но не загружаются и не читаются.

## Сохранённый корпус

Пример manifest.json:

```json
{
  "pages": {
    "https://factory.test/": {"path": "home.html"},
    "https://factory.test/catalog/pump/": {"path": "pump.html"},
    "https://factory.test/old/": {"error": "not_found"}
  },
  "resources": {
    "https://factory.test/robots.txt": {"path": "robots.txt"},
    "https://factory.test/sitemap.xml": {"path": "sitemap.xml"}
  },
  "card_outcomes": {
    "https://factory.test/catalog/pump/": {
      "count": 0,
      "source": "предыдущий_прогон/product_result.json"
    }
  }
}
```

Пути разрешаются относительно manifest; исходники разрешено читать за пределами
выходного каталога. Они не изменяются. HTML должен быть UTF-8; ресурсы sitemap —
уже распакованные HTTP-тела. Необязательные поля записи: `status`, `final_url`,
для resources также `content_type`. Для товарного fragment нужно перечислить
точный URL состояния; из HTML оно выделяется штатным изолятором, иначе сохраняется
`saved_state_missing`. Записи manifest не становятся стартовыми URL автоматически:
обход начинает с переданного адреса и явно заданных контрольных страниц.

`card_outcomes` — необязательное свидетельство прежнего прогона с числом карточек
и источником. Ноль даёт признак `zero_cards_previous_run`, участвующий в выборке;
это не результат нового извлечения. Отсутствующее число не заменяется нулём.

## Карта, группы и выборка

В `structure.json` сохраняются:

- опубликованный URL, нормализованный ключ, альтернативные написания и источники
  (sitemap, родительская страница, пагинация, штатный сборщик, контрольный URL);
- допуск/исключение, попытка загрузки, фактический URL, транспорт, состояние и причина;
- URL-роль штатного классификатора и отдельно оценка содержимого; конфликт не скрывается;
- совмещение профильных ролей контактов и поставщиков;
- структура URL, структура HTML, признаки таблиц, списков, вкладок, сеток и пагинации;
- выбранный шаблон v2 либо ошибка неоднозначности; версии и SHA256 профиля/зависимостей;
- список попыток, группы, выбранные примеры, ограничения, SHA256 исходников и входных файлов.

Нормализатор используется для идентичности; `url_shape` служит только группировке.
Он сохраняет хост, промежуточные сегменты пути, тип листового сегмента/расширение,
имена query-параметров и наличие товарного состояния. Значения query и fragment
остаются в ключах отдельных страниц. Числовые сегменты группируются как числа.
HTML-группа — хеш множества структурных путей основного DOM до глубины 8, без
текста, повторений одинаковых строк, навигации и служебных тегов. Итоговая группа
учитывает URL-роль, обе структуры и выбранное правило профиля. Это эвристика:
она не доказывает семантическую одинаковость страниц и не создаёт правила автоматически.

Очередь чередует URL-группы, сохраняя доступ к главной, каталогам и контактам.
Контрольные URL приоритетны; отложенные проверки выполняются после основной части.
Выборка сначала покрывает новые группы, затем новые признаки. В неё входят
отрицательные примеры, ошибки загрузки и известный прежний нулевой выход.
Обязательные пользовательские URL не теряются при малом sample: превышение
отмечается как `mandatory_sample_overflow`. Если для них недостаточен лимит urls,
запуск завершается ошибкой. Непокрытые группы явно перечислены как несэмплированные.

Принудительные URL имеют `forced=true`; поле `independently_discovered` показывает,
была ли ссылка найдена также самостоятельно. Holdout не раскрывает свои ссылки
основному обходу и не засчитывается как покрытие группы обучающей выборкой.
При отсутствии holdout остаётся `holdout_not_provided`.

Человекочитаемая выборка — `sample.tsv`; краткая сводка — `SUMMARY.txt`.
Загруженные HTML сохраняются в `html/` (ключ имени — SHA256 URL и индекс состояния).
При ошибке самого запуска сохраняется `error.json`. Код возврата 0 означает
готовый отчёт, а не готовность профиля или полноту охвата.

## Ограничения покрытия

Лимиты страниц, URL, времени, глубины, пагинации и sitemap никогда не означают
успешную полную перепись. Для неизвестного остатка за лимитом сохраняется причина;
судьба каждого URL описывается только в пределах реально наблюдённого набора.
Ссылки, не увиденные из-за недоступной карты/страницы, невозможно перечислить.

Реальные динамические загрузки выполняет существующий краулер; все возвращённые
им состояния дают ссылки и структурные признаки. Новый этап не нажимает
произвольные кнопки «Показать ещё» и не гарантирует исчерпание бесконечной прокрутки.
Оставшийся динамический каркас/кнопка создаёт `dynamic_not_exhausted`; несколько
состояний одного URL — `multiple_states_need_review`. Последующая живая проверка
должна закрыть эти ограничения. Статический HTML не доказывает работу взаимодействий.

Отсутствие товарного сигнала в HTML не считается доказанным отсутствием карточек.
Карточки и качество Markdown проверяются последующими задачами плана. Сохранённые
страницы не подтверждают актуальность живого сайта. Статус покрытия относится
только к наблюдённым URL; полную приёмку профиля он не заменяет.

Этап запускается отдельно либо на сохранённом корпусе через
[постоянную очередь задачи 6](PROFILE_QUEUE.md). Обновление снимка
`profile-review` остаётся задачей 8; живой режим в очередь пока не подключён.
