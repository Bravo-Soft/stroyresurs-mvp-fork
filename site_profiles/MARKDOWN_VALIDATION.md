# Проверка сохранения HTML → Markdown

Версия проверяющего модуля 3: сохранены номера пунктов исходных абзацев,
ссылки со скобками в адресе, исправлены дублирование обёрток h5/h6 и
склейка степени единицы со следующей ценой. Проверки настоящих изменений
чисел, единиц и заголовков сохранены (10 регрессионных сценариев).

В версии 2 добавлена эквивалентная запись λ/«лямбда»,
исправлен контекст соседних заголовков одного уровня. Заголовок должен остаться
заголовком, простой абзац с тем же текстом его не заменяет. Версия manifest — 1.

Задача 5: независимое сравнение содержательных блоков, таблиц, чисел, единиц и
примечаний, обнаружение интерфейсного и скрытого служебного текста в Markdown.
`markdown_validation.py` не вызывает конвертер, его очистку, LLM или сеть.
`check_markdown.py` выполняет пакетную проверку сохранённых материалов; при
необходимости отдельно запускает штатную генерацию Markdown с выбранным профилем.

## Запуск

Из рабочей копии исходников:

```bash
python -B -m site_profiles.check_markdown \
  --manifest /ai/projects/stroy-resurs/codex_work/входы/manifest.json \
  --output /ai/projects/stroy-resurs/codex_work/проверки/новый_прогон \
  --profiles /ai/projects/stroy-resurs/codex_work/кандидаты
```

`--profiles` нужен только для страниц без готового `markdown`. Каталог результата
должен быть новым и находиться внутри проектного `codex_work`; проверяется путь
после разрешения symlink. Прежние каталоги не очищаются и не перезаписываются.
CLI запрещает сетевые connect/bind/DNS через Python audit hook. Пайплайн,
генераторы карточек, загрузчики файлов и графа не запускаются; исходники читаются.

Код возврата 0 означает сохранённый отчёт, **не принятие профиля**. При ошибке
настройки запуска возвращается 2. Ошибка отдельной страницы сохраняется и не
мешает проверить остальные; пакет получает fail. Результат читается из status.

## Независимый эталон

Пример manifest.json:

```json
{
  "version": 1,
  "pages": [
    {
      "url": "https://factory.test/catalog/pump/",
      "html": "pump.html",
      "markdown": "pump.md",
      "model_input": "captured_source_text.txt",
      "split": "control",
      "reference": {
        "selectors": ["main", "#specifications", ".technical-notes"],
        "origin": "Независимая проверка исходной страницы, дата и ссылка на доказательства",
        "public_selectors": [],
        "exclusions": [
          {"selector": ".promotion", "reason": "Рекламное предложение, вне описания изделия"}
        ]
      }
    },
    {
      "url": "https://factory.test/catalog/another/",
      "html": "another.html",
      "split": "holdout",
      "reference": {
        "selectors": ["main"],
        "origin": "Отдельная контрольная страница, не использованная при подборе правил"
      }
    }
  ],
  "structure_report": "../обнаружение/structure.json"
}
```

Пути считаются относительно manifest. HTML/Markdown/вход модели — UTF-8.
`page_type`, если нужен при генерации: пустая строка для товара, `company` либо
`distributor`. Передача готового Markdown не требует профилей. PDF/DOCX не
поддерживаются как источники фактов.

**reference не строится из remove_selectors или выбранного контейнера конвертера.**
Иначе ошибка профиля исключила бы один блок одновременно из результата и эталона.
Нужно самостоятельно задать содержательную область, включая таблицы/примечания
вне основного контейнера. Исключение эталона требует причины и попадает в отчёт.
`origin` фиксирует происхождение решения, но сам текст этого поля не доказывает
правильность выбранной области: её смысловая проверка остаётся обязательной.

Без selectors проверяется очищенный от явного UI body, но область считается
эвристической: `source_scope_inferred`. Предполагаемые потери получают severity
`review`, а не подтверждение дефекта. Надёжно опознанный UI/скрытый служебный текст
может дать error независимо от такой неопределённости.

Публичная заполненная панель включается по связи с видимым управляющим элементом
`aria-controls`, `data-target`/`data-bs-target` или якорной ссылкой. Дополнительные
панели можно задать через public_selectors при наличии внешних доказательств.
Доступность панели не делает доступными её собственные скрытые дочерние узлы.
Несвязанная скрытая вкладка даёт неопределённость. Наличие HTML-связи не заменяет
живую проверку клика и CSS/вычисленных стилей в браузере.

## Что сравнивается

- Заголовки, абзацы, списки, определения `dt → dd`, текстовые блоки и примечания.
  Полнота проверяется внутри контекста раздела, а не по числам во всём документе.
- Таблицы разбираются независимо от MarkdownConverter: раскрываются rowspan/colspan,
  учитываются многоуровневые заголовки, подписи и заголовок на всю ширину.
- Сопоставляются строки и значения под соответствующими заголовками. Корректная
  перестановка строк/столбцов допустима; обмен значений между моделями — ошибка.
  Числа, продублированные в другом абзаце, не компенсируют потерю ячеек.
- Поддерживаются GFM-таблицы, экранированный `\|`, `<br>` в ячейках и отдельные
  HTML-таблицы в Markdown. Примечание может остаться в таблице или перейти в
  абзац своего контекста. Маркеры примечаний сохраняются.
- Числа, знаки, допуски, единицы и степени проверяются вместе с контекстом.
  Десятичная запятая/точка, пробел тысяч, `м³`/`м^3`/`м3`, варианты знака минуса,
  температурного градуса и разделителя размеров нормализуются. Значения и единицы
  не пересчитываются: `МПа` не равен `кПа`, `м²` не равен `м³`, `−5` не равен `5`.
  Марка стали `20Х13` не приравнивается к размеру `20х13`.
- Текст навигации, форм, кнопок, меню, пагинации и cookie-блоков проверяется на
  попадание в Markdown, включая ячейки таблиц. Совпадающая легитимная подпись
  содержательного блока не объявляется шумом автоматически.

Каждый сигнал содержит код, важность, ожидаемое и фактическое содержимое, DOM-путь,
контекст и строку Markdown. Для нарушенной строки таблицы сохраняются заголовки,
номер строки и различия по ячейкам. SHA256 фиксируют входы и код проверки.

Нормализация намеренно ограничена. Это проверка сохранения представления, а не
семантический LLM-судья и не доказательство равенства произвольных перефразировок.
Вложенные/непрямоугольные таблицы, неоднозначное сопоставление, неподдерживаемая
разметка и графики/canvas отмечаются как uncertain. Сведения из изображений,
вложений, JSON-LD и скрытых служебных данных не становятся эталоном карточки.

## Фактический вход модели

`model_input` должен ссылаться на сохранённый текст источника **после** обрезки и
обработки больших таблиц, реально переданный модели. Проверка повторяется отдельно
для него; потери получают stage=model_input. Подготовленный самим оператором
текст нельзя выдавать за захват настоящего вызова.

Если файла нет, выполняется только предварительная проверка `markdown[:100000]`
(лимит можно задать --model-char-limit). Она имеет stage=simulated_model_input и
kind=simulation_not_capture. Прогнозируемая потеря блокирует пакет; отсутствие
потерь в прогнозе не подтверждает настоящий вход. Страница без captured input
не получает окончательный pass пакетной проверки. LLM при этом не вызывается.

Библиотечный `check_markdown` отдельно возвращает статус Markdown и поле model_input:
без переданного входа последнее остаётся uncertain. Пакетный CLI дополнительно
ограничивает итоговый статус всей страницы, как описано выше.

## Связь с обнаружением структуры и контрольными страницами

Необязательный structure_report связывает пакет с задачей 4. Проверяется наличие
всех выбранных URL; открытые ограничения обнаружения не обнуляются успехом Markdown.
Пакет сохраняет control/holdout отдельно. Отсутствие holdout либо тот же URL в
обеих группах оставляют неопределённость. Пометка holdout не доказывает независимость
истории подбора правил; это проверяется по происхождению пакета.

Исходный снимок `codex_work/profile_review` не обновляется этим инструментом.
Пакетная проверка подключена к изолированной [очереди задачи 6](PROFILE_QUEUE.md).
Обновление скилла остаётся задачей 8.

## Статусы и артефакты

- pass: заявленный локальный контракт проверен, обязательные входы пакета присутствуют.
- fail: есть ошибка сравнения либо ошибка обработки страницы.
- uncertain: недостаточно сведений об эталоне, панели, структуре, фактическом входе
  модели или контрольном покрытии; это не успешная приёмка.

В корне результата: `summary.json`, `pages.tsv`, `SUMMARY.txt`. Для каждой страницы
создаётся отдельная папка с source.html, markdown.md, result.json, captured либо
simulated текстом входа. Сбои сохраняются в error.json. Исторические материалы
не изменяются; source exclusions и пути резервного извлечения видны в отчёте.

Даже pass не подтверждает свежесть живой страницы, качество карточек, порог ТХ,
полноту всего сайта или готовность профиля к применению. Эти проверки выполняются
на следующих этапах плана и по действующему контракту приёмки.
