# Формат профиля сайта: схема 2

Профили без `schema_version` читаются как схема 1 без изменения их настроек.
`profile_version` — редакция сайта, `schema_version` — версия формата. Сейчас
поддерживаются 1 и 2. Новые возможности требуют `schema_version: 2`.
Номер редакции сайта и версии подключаемых правил увеличиваются при изменениях.
Контрольные суммы дополнительно выявляют изменение содержимого при том же номере.

Пример: [demo.example.yaml](examples/v2/demo.example.yaml) и
[_rules.yaml](examples/v2/_rules.yaml). Они расположены во вложенной папке и
не загружаются как рабочие профили сайта. Реальные сайты этой задачей не меняются.

## Общие правила и наследование

В каталоге рабочих YAML может находиться один `_rules.yaml`:
`schema_version: 2`, положительная `version`, `defaults`, `groups`.
Подключение явно задаётся в сайте через `extends.rules_version`; без `extends`
общие правила на сайт не действуют. Группа необязательна; для неё нужны
`extends.group` и точная `extends.group_version`. Группа содержит `version`
и `settings`. Отсутствующий файл, группа или несовпадение версий — ошибка.
В общих настройках и группе разрешены только `crawl`, `sections`, `extract`.
Цепочки наследования групп и включение произвольных файлов не поддерживаются.

Порядок: defaults → выбранная группа → сайт → выбранный шаблон страницы.
Словари объединяются рекурсивно; списки целиком заменяются. Отсутствующее поле
наследуется. Явные `false` и `[]` заменяют родительские значения. `null` заменяет
значение только там, где схема допускает null (например, контейнер или лимит).
`{}` не очищает родительский словарь. Для отключения очистки задайте
`remove_selectors: []`; для отключения шаблонов — `page_rules: []`.

Резолвер следит также за изменением `_rules.yaml`. Зависимости и SHA256 входят
в `profile.diagnostics`: по ним определяется перечень затронутых профилей.
Перезагрузка не означает повторную приёмку. При смене общих правил доказательства
по предыдущему SHA256 нельзя выдавать за проверку новой редакции.

## Шаблоны страниц

`extract.page_rules` — список правил с уникальным непустым `name`, целочисленным
`priority` (по умолчанию 0), непустым `match` и необязательным `extract`.
Все условия match применяются одновременно:

- `page_types`: список из `product`, `company`, `distributor`. При отсутствии — все три.
- `path_regex`: Python regex, `re.search` по path URL, без схемы, query и fragment.
- `selector`: наличие CSS-элемента в DOM после выделения публичного состояния,
  до удаления профильных блоков. Служебные значения не являются источником ТХ.

Выбирается совпавшее правило с максимальным priority. Несколько совпадений
на этом приоритете вызывают `ProfileRuleError`, перечисляющий правила.
Произвольное пересечение регулярных выражений не вычисляется статически:
неоднозначность проверяется на конкретной странице, её надо покрывать контрольными URL.
Без совпадения сохраняются настройки сайта. Исходный объект резолвера не меняется.

Шаблон может переопределять только поля extract; вложенные page_rules запрещены.
Классификацию URL и загрузку страниц он не меняет: это по-прежнему crawl/sections.
`cluster`, `llm_program`, tier `jsonld`/`cms` в схеме 2 отвергаются как пока
неисполняемые; для общих правил используется extends, для извлечения — llm/custom.

## Содержательные блоки и исключения

`extract.markdown.content_blocks` — список `{name, selector, required}`.
Имена уникальны, selector — CSS; required по умолчанию false. Каждый селектор
может выбрать несколько узлов, они следуют в порядке DOM внутри этого правила.
При наличии типового product/company/distributor_container он идёт первым и
считается обязательным, затем идут content_blocks в объявленном порядке.
Без контейнера content_blocks полностью определяют область извлечения.

Повторно выбранный узел выводится один раз. Если выбраны родитель и потомок,
остаётся родитель; порядок оставшихся узлов определяется списком селекторов.
Обязательный блок должен содержать текст или изображение после профильного
удаления, удаления script/style/noscript/template и недоступных скрытых узлов.
Отсутствие обязательного блока или всех выбранных блоков — ProfileRuleError,
а не пустая успешная карточка и не переход на весь документ.

Без content_blocks действует контракт задачи 2: найденный явный контейнер
приоритетнее адаптера и автоматики; отсутствующий контейнер допускает резервный
путь с записью причины. С content_blocks область строгая, без расширения.

- `crawl.exclude_paths` запрещает обход по существующим правилам краулера.
- `sections.product_url_antipatterns` запрещает товарную роль, не весь обход.
- `extract.markdown.remove_selectors` удаляет узлы из выбранного содержимого.
  В шаблоне этот список заменяет список сайта, поэтому нужные общие исключения
  следует повторить явно, если шаблон меняет список.

Характеристики берутся только с видимой страницы, включая публичные вкладки.
keep_hidden_tabs сохраняет существующий opt-in профиля; сам флаг не доказывает
видимость блока. PDF/DOCX и скрытые служебные данные не служат источником карточки.

## Адаптер и валидация

`tier: custom` требует `custom_module` — имя существующего Python-модуля в
Profile_Markdown без пути и расширения. Шаблон может выбрать иной адаптер.
При заданной явной области (контейнер/блоки) применяется прямой конвертер,
адаптер extract не вызывается. Без явной области применяется выбранный адаптер;
его None запускает резервное извлечение по контракту задачи 2. Очистка профиля
сохраняется также для needs_raw_html. Программная ошибка товарного адаптера
не маскируется успешным резервным результатом.

В v2 проверяются типы, неизвестные поля, CSS, regex, положительная редакция,
непротиворечивые min_len/max_len, структура блоков/шаблонов, имя и наличие
адаптера. Загрузчик дополнительно проверяет ссылки и совпадение домена с именем
файла. Домен — ASCII/punycode без схемы и пути. Повторяющиеся YAML-ключи и
рекурсивные алиасы запрещены. Файлы и общие правила проходят один и тот же loader.
Ошибочный явно версионированный профиль не заменяется generic для своего домена.
Для старых неверсированных файлов сохраняется прежняя политика загрузчика.

`profile_from_dict` проверяет эффективный словарь, но не читает файлы групп.
Для полной проверки необходимо сначала compose(data, profiles_dir) либо загрузить
ProfileResolver. Валидация диспетчерской использует тот же порядок.
Перепись сохраняет исходные ручные правила v2 и их ссылки, обновляя метрики,
дату и редакцию; она не подменяет шаблоны эвристическими настройками.

## Диагностика без сети и записи

Из mvp либо рабочей копии:

```bash
python -B -m site_profiles.inspect_profile https://demo.example/catalog/pump \
  --profiles profiles/examples/v2 --html /путь/к/сохранённой/странице.html
```

Без --html выводится профиль после объединения. С HTML — выбранный шаблон,
эффективные настройки, происхождение полей, SHA256 правил и адаптера.
Тип страницы задаётся --page-type product/company/distributor.
CLI не выполняет краулинг, вызовы LLM или запись в граф.
События profile_rule сохраняются в метриках profile_rules; ошибки выбора/блоков
также регистрируются через markdown_fallbacks с причиной и URL.

Формальная корректность YAML не заменяет приёмку покрытия и качества.
Снимок инструмента codex_work/profile_review обновляется отдельной проверкой
на этапе обновления скилла; несовпадение его исходников не следует обходить
ручной сменой manifest. Схема 2 сама по себе не разрешает применение профиля.
